# INC-004 — Local wording rewrite

## Executive Summary

This increment lets a local model rewrite loose wording into the closed grammar before the parser runs. If the model fails, the parser runs on the original phrase.

The requirements are already met by INC-002 and INC-003. This increment covers the on-prem wording step. Tests must not download weights.

## Increment Identity

#### Increment Identity

**Increment ID**: INC-004
**Increment Name**: Local wording rewrite
**FR Mapping**: None (NFRs; the parser already satisfies the functional requirements)

## Goal

#### Goal

The shop can rewrite a phrase with a local model cached in the image, and a failed rewrite still returns the parser result.

## Dependencies

#### Dependencies

INC-002 Phrase parser
INC-003 Search results

## Plan

#### Plan

1. Add `@huggingface/transformers` at version 4.3.0 to `package.json`.
2. Add `rewritePhrase(phrase)` in `lib/phrase-limits.js` that asks `Xenova/flan-t5-small` for one line using `under N`, `over N`, `between A and B`, `age N`, `ages A-B`, and leftover theme words.
3. Change `parsePhrase` so it parses the rewritten line when that call returns text, and parses the original phrase when the call throws or the rewritten line is not the closed grammar.
4. Load the pipeline once per process. Do not call the Hugging Face hosted API.
5. In `Dockerfile`, after `npm install`, download `Xenova/flan-t5-small` into a cache directory in the image and set the runtime to read that cache only.
6. Add a test that passes a fake rewriter returning `under 50` for `cheaper than 50`, and a test that passes a rewriter that throws and still parses `under 50` from the original phrase.
7. Do not assert the real model in `npm test`.

## Outcome

#### Outcome

- A failed model call still returns parser bounds
- A fake rewriter can change wording before the parse
- The image build caches the model
- `npm test` exits 0 without network
