# INC-003 — Search results

## Executive Summary

This increment connects the parser to `GET /search` and shows the interpreted limits on `views/search.ejs`. An empty phrase stays the current list.

The age check runs before the page is cut to 20. The limits line is escaped. Theme wildcards are escaped. Sort stays the discounted English price. The price filter uses list price.

## Increment Identity

#### Increment Identity

**Increment ID**: INC-003
**Increment Name**: Search results
**FR Mapping**:

- FR1.1.2 When the phrase yields none of those three, the system shall show no products. It shall not fall back to the full list or to an English-name match.
- FR1.1.3 When the phrase yields one or more of those three, the system shall show only products that satisfy every yielded limit.
- FR1.1.4 The system shall treat a distinctive part of a stored theme name as a match, and shall include products from every theme that part matches.
- FR1.1.5 When the phrase gives one age, the system shall keep a product only when that age falls inside the stored age text. "age 8" and "8 years old" match "6–12". "age 12" and "12 years old" match both "6–12" and "12+". The system shall treat a number as an age only when the phrase says age or years old. When the phrase gives an age range that way, such as "ages 5-12" or "between 5 and 12 years old", the system shall keep a product only when that range overlaps the stored age text. Both ends count. A between-pair or a hyphen pair with neither of those words is a price bound.
- FR1.1.7 The system shall show matching products on the current results list, 20 at a time.
- FR1.1.8 When the phrase yields one or more limits, the system shall show those interpreted limits on the search page along with the product list, including when that list has no products. When the phrase yields none, there are no limits to show.
- FR2.1.1 When the user opens search and submits no phrase, the system shall keep today's list: products 20 at a time, cheapest first.
- FR2.1.2 The system shall keep the separate price-order and category controls, including dropping the typed phrase when either control changes.
- FR2.1.3 The system shall keep opening search from the header without signing in, paging, and opening a product from the list.

## Goal

#### Goal

A phrase on the search page filters products by the parsed bounds and shows those bounds, and a blank search still shows today's list.

## Dependencies

#### Dependencies

INC-002 Phrase parser

## Plan

#### Plan

1. In `index.js` `GET /search`, trim `keyword`. When it is empty, keep the current name-match queries, including the existing count read.
2. When the trimmed keyword is not empty, call `parsePhrase`. If it returns no bounds and no theme, render `products` as an empty array and do not pass limits.
3. Otherwise query `product` with bound predicates only: `p_price_en <= ?` when `priceMax` is set, `p_price_en >= ?` when `priceMin` is set, and `p_category LIKE ?` when `theme` is set. When `category` is not `all`, also add `p_category = ?` with that value. Escape `%`, `_`, and `\` in the theme fragment before wrapping it as a contains-match. Do not filter `p_name_en` on this path.
4. Keep `ORDER BY discounted_price` for `price-asc` and `price-desc`. Do not put `LIMIT` in this query.
5. Drop rows for which `ageOverlaps` is false when an age bound is set. Then slice the filtered rows to 20 using the existing page offset, and set `totalPages` from the filtered length.
6. Pass `limits` to `views/search.ejs` only when at least one bound or theme exists. Render that line with `<%= %>` above the product grid, including when the grid is empty.
7. Leave the category form without a keyword field. Leave header, paging links, and product links as they are.
8. On query failure, keep `console.error` and `res.status(500).send("Database query error")`. Do not log the phrase.
9. Add a unit test that filters a fixture list by age before slicing to 20.

## Outcome

#### Outcome

- A phrase with no bounds shows no products and no limits line
- A phrase with bounds shows only rows that match every bound, 20 per page, counted after the age filter
- The limits line is escaped shopper text
- An empty keyword still uses the current query
- `npm test` exits 0
